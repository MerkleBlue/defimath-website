4:T321c,<p>v4.0.0 is the first major release since v3.0.0, and it earns the version bump two
ways: a <strong>new Black-76 module</strong> for pricing European options on a future, and a
<strong>library reorganization</strong> that gives every module a name that reads like its
math. The reorg changes import paths and call sites, so upgrading is not
drop-in — a short migration guide is at the bottom.</p>
<h2>Black-76: European options on a future</h2>
<p><a href="/docs/black-76/">Black-76</a> prices dated European options whose underlying is a
<strong>future</strong>, not a spot price — the standard model for options on commodity,
rate, and crypto futures. It ships the same surface as Black-Scholes: <code>call</code>,
<code>put</code>, the four Greeks (<code>delta</code>, <code>gamma</code>, <code>theta</code>, <code>vega</code>), and a
Newton-Raphson <code>impliedVolatility</code> solver.</p>

<p>Under the hood Black-76 is Black-Scholes with the underlying set to the future
<code>F</code> and the rate zeroed inside <code>d₁</code>, with the whole payoff discounted by
<code>e^(−rT)</code>:</p>
<pre><code>price = e^(−rT) · [ F·Φ(d₁) − K·Φ(d₂) ]        (call)
d₁ = [ ln(F/K) + σ²T/2 ] / (σ√T),   d₂ = d₁ − σ√T
</code></pre>
<p>That structure is reused verbatim from the <a href="/docs/black-scholes/">Black-Scholes</a>
kernel — the same <code>stdNormCDF</code>, <code>exp</code>, and <code>ln</code> primitives — so it inherits the
same precision and the same gas discipline. Prices hold to <strong><code>5e-12</code> relative
error</strong> (<code>1.3e-10</code> absolute deep out-of-the-money), verified in CI against a
<code>black-scholes</code>/<code>greeks</code> reference driven through the discounting identity.</p>
<h2>A cleaner API — and why this is v4.0.0</h2>
<p>Every library dropped its <code>DeFiMath*</code> prefix, and the two derivative modules got
names that say what they are. The library namespace now carries the context, so
functions shed their redundant prefixes too — <code>DeFiMathOptions.callOptionPrice</code>
is just <code>BlackScholes.call</code>. The old <code>contracts/finance/</code> folder split into
<code>contracts/rates/</code> and <code>contracts/statistics/</code>.</p>

<p>Two function families were also renamed now that the library name carries the
context:</p>
<ul>
<li><strong>Black-Scholes</strong> — <code>callOptionPrice → call</code>, <code>putOptionPrice → put</code>. The
Greeks (<code>delta</code>, <code>gamma</code>, <code>theta</code>, <code>vega</code>, <code>impliedVolatility</code>) keep their
names.</li>
<li><strong>Binary options</strong> — the <code>binary</code> prefix is gone: <code>binaryCallPrice → call</code>,
<code>binaryPutPrice → put</code>, <code>binaryDelta → delta</code>, <code>binaryGamma → gamma</code>,
<code>binaryTheta → theta</code>, <code>binaryVega → vega</code>.</li>
</ul>
<p>No formula, precision, or gas number changed in the rename — only the names and
import paths.</p>
<h2>Bugfix: expired put delta</h2>
<p><code>BlackScholes.delta</code> returned <code>+1</code> for the put leg of an in-the-money option at
expiry (<code>timeToExp == 0</code>); the correct value is <code>−1</code>. Fixed, with a regression
test that fuzzes moneyness at expiry and asserts the delta bounds and put-call
delta parity. The call leg and every non-expiry case were already correct. The
new <a href="/docs/black-76/">Black-76</a> module handles this case correctly from the
start.</p>
<h2>Precision &#x26; docs</h2>
<p>Every derivative function now carries full NatSpec — parameter semantics, the
error metric, and the enforced bound — matching the format already on the math
primitives. Where a function has both a relative and an absolute guarantee
(price-like outputs near zero), both are documented and published: relative
error where <code>|result| ≥ 1</code>, absolute where <code>|result| &#x3C; 1</code>.</p>
<h2>Testing</h2>
<p>Black-76 ships with the same two-layer coverage as the rest of the library —
100 Hardhat correctness tests (validated against the discounting identity) and
16 Foundry properties (put-call parity, delta parity <code>δcall − δput = e^(−rT)</code>,
discounted bounds, monotonicity, IV round-trips). The suite totals grow to
<strong>740 Hardhat tests</strong> and <strong>114 Foundry properties × 32,000 runs = 3,648,000
random executions per CI run</strong>.</p>
